# 0.3.4 自動同期の修正と実動作検証

2026-09-06、Windows版の実行ファイルで検証。

## 原因と修正

Codexの`thread_history_1.sqlite`に残るターン情報が更新されず、実際には応答中でも過去の`interrupted`が取得されていた。
表示名は従来どおり`state_5.sqlite`の`name`を使い、状態は同DBが指す履歴JSONLのライフサイクルイベントを優先する。
Windowsの`\\?\`形式のパスにも対応した。Codexデータは読み取り専用。

初回は末尾から最新イベントを検索し、以後は追記部分を2秒間隔で読む。書きかけの行は次回まで待つ。
会話レコードを読み取るが、本文は保持・表示・送信せず、状態とイベント識別子だけを保持する。
履歴を読めない場合はDBにフォールバックし、遅延の可能性を説明に表示する。
